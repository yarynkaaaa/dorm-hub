# Компонентна архітектура DormHub: стан і взаємодія

## Карта стану

| Значення                                | Призначення               | Початковий стан  | Власник                          | Споживачі                                                | Скидання                                       |
| --------------------------------------- | ------------------------- | ---------------- | -------------------------------- | -------------------------------------------------------- | ---------------------------------------------- |
| selectedRoomId                          | Обрана кімната для заявки | null             | HostelProvider                   | RoomCard, SettlementForm, SelectionChip, ефект заголовка | clearSelection (кнопка «Очистити»)             |
| filters { query, floor, onlyAvailable } | Умови відбору кімнат      | "", "all", false | RoomsPage (через useRoomFilters) | RoomFilters, обчислення visibleRooms                     | resetFilters                                   |
| expanded                                | Показ деталей картки      | false            | кожна RoomCard окремо            | розмітка цієї картки                                     | кнопка «Деталі» перемикає                      |
| places                                  | Кількість потрібних місць | 1                | кожна RoomCard окремо            | степпер цієї картки                                      | повертається до 1 при новому монтуванні картки |
| draft { fullName, group }               | Чернетка заявки           | "", ""           | SettlementForm                   | поля форми, DraftSummary                                 | кнопка «Очистити»                              |
| submitted                               | Підготовлена заявка       | null             | SettlementForm                   | повідомлення про успіх                                   | зміна будь-якого поля, «Очистити»              |

### Похідні значення (окремого useState не потребують)

- visibleRooms і floors: обчислюються з rooms і filters у useRoomFilters.
- selectedRoom: знаходиться за selectedRoomId у HostelProvider.
- totalFree, totalCapacity: підсумки в RoomsPage.
- availableRooms, canSubmit: обчислюються у SettlementForm.

## Область провайдера

HostelProvider огортає Layout і обидві сторінки. Споживачі в різних гілках: SelectionChip (шапка), RoomCard (кімнати), SettlementForm (заявка). Локальними лишено filters, expanded, places, draft, submitted.

## Контракти подій

| Подія                   | Хто викликає                        | Що відбувається                           |
| ----------------------- | ----------------------------------- | ----------------------------------------- |
| selectRoom(id або null) | RoomCard, select у SettlementForm   | Змінює selectedRoomId для всіх споживачів |
| clearSelection()        | кнопка «Очистити»                   | selectedRoomId = null                     |
| updateFilters(patch)    | RoomFilters                         | Зливає зміни в filters                    |
| resetFilters()          | кнопка «Скинути», «Скинути фільтри» | Повертає початкові умови                  |
| handleField(event)      | поля ПІБ і групи                    | Оновлює draft за name поля                |

## Ефект

HostelProvider синхронізує document.title із номером обраної кімнати. Залежність: номер кімнати. Очищення повертає попередній заголовок. У StrictMode ефект запускається двічі в розробці, але очищення робить результат коректним.

## Рішення щодо Context

Context застосовано лише до вибору кімнати: цей стан потрібен трьом віддаленим гілкам, а передавати його пропсами довелося б через Layout, Header і дві сторінки. Фільтри, чернетку та стан карток залишено локальними: ними користується лише одне місце, а контекст перерендерював би зайве. Рішення варто зберегти в проєкті, а при появі користувачів і ролей контекст автентифікації додається за тією ж схемою.
