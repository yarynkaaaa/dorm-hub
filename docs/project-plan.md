# DormHub: план проєкту

## 1. Назва та опис

**DormHub** — веб-сайт для управління студентським гуртожитком: облік мешканців і кімнат, поселення й виселення, оплата проживання.

## 2. Ролі

| Роль          | Можливості                                                        |
| ------------- | ----------------------------------------------------------------- |
| Адміністратор | Керує акаунтами та ролями, має повний доступ до даних і звітів    |
| Комендант     | Переглядає кімнати, поселяє й виселяє мешканців, веде облік оплат |
| Мешканець     | Переглядає власну кімнату та історію оплат                        |

## 3. Вимоги

### Функціональні

- Перегляд кімнат із кількістю вільних місць і статусом заповнення.
- Облік мешканців: ПІБ, факультет, група, контакти.
- Поселення мешканця в кімнату з перевіркою вільних місць.
- Виселення мешканця із фіксацією дати.
- Облік оплат проживання та перелік боржників.
- Вхід у систему та розмежування доступу за ролями.
- Пошук і фільтрація.

### Нефункціональні

- Коректне відображення на ПК і телефоні.
- Запуск однією командою локально та в Docker.
- Паролі лише у вигляді хешів, доступ за ролями.
- Код організовано за частинами: дані, компоненти, сторінки.

## 4. Сценарії

| №   | Сценарій                                  | Роль      | Стан                                                    |
| --- | ----------------------------------------- | --------- | ------------------------------------------------------- |
| 1   | Перегляд кімнат і наявності вільних місць | Комендант | Реалізовано в Л 1.1, збережено в Л 1.2                  |
| 2   | Поселення мешканця: подання заявки        | Комендант | Форма заявки реалізована в Л 1.2 (без збереження даних) |
| 3   | Виселення мешканця                        | Комендант | Заплановано                                             |
| 4   | Облік оплат і список боржників            | Комендант | Заплановано                                             |
| 5   | Вхід за ролями                            | Усі       | Заплановано                                             |
| 6   | Перегляд власної кімнати й оплат          | Мешканець | Заплановано                                             |

## 5. Попередня модель даних

| Сутність                  | Основні поля                                           |
| ------------------------- | ------------------------------------------------------ |
| Resident (мешканець)      | id, ПІБ, факультет, група, телефон                     |
| Room (кімната)            | id, номер, поверх, місткість                           |
| Accommodation (поселення) | id, мешканець, кімната, дата заселення, дата виселення |
| Payment (оплата)          | id, мешканець, сума, період, дата, статус              |
| User (акаунт)             | id, логін, хеш пароля, роль                            |

## 6. Технології

- Frontend: React (Vite), JavaScript, власні стилі.
- Середовище: Node.js (LTS), npm, Git, Docker, Visual Studio Code.
- Backend і БД: будуть обрані на наступних етапах.

## 8. Що буде далі

1. Додати збереження заявок і перехід від заявки до фактичного поселення.
2. Додати сторінки мешканців, виселення й оплат.
3. Спроєктувати схему бази даних за моделлю з розділу 5.
4. Реалізувати серверну частину й замінити дані-заглушку запитами до API.
5. Додати вхід у систему та розмежування доступу за ролями.
6. Додати пошук і фільтри, провести тестування.
